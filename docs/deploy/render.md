# Deploy the vendor backend to Render

The vendor backend (`backend/`, Express + firebase-admin) runs as a Render web service. It reads and
writes Firestore in Firebase project **glowvai-v2**, stores product photos in Firebase Storage, and
publishes approved products to the Firestore collection `products`, which the website's /shop reads.

`render.yaml` at the repo root describes the service. In production the server refuses to start
unless `VENDOR_TOKEN_SECRET`, `ADMIN_API_KEY` and Firebase credentials are set, so a missing
variable shows up as a failed deploy, not as a silently empty in-memory backend.

## 1. Firebase console (project glowvai-v2)

1. Open https://console.firebase.google.com and select **glowvai-v2**.
2. **Firestore**: Build > Firestore Database. If it is not created yet, click **Create database**
   (production mode, region `asia-south1` if you are choosing now). No composite indexes are needed:
   the backend only uses equality filters.
3. **Storage**: Build > Storage > **Get started**. Note the bucket name shown at the top of the Files
   tab. For this project it is `glowvai-v2.firebasestorage.app`. If yours shows
   `glowvai-v2.appspot.com`, use that value for `FIREBASE_STORAGE_BUCKET` in step 2.
   The backend writes with the Admin SDK and returns `https://firebasestorage.googleapis.com/...`
   download URLs that carry a token, so the default Storage rules can stay locked.
4. **Service account key**: Project settings (gear icon) > **Service accounts** > Firebase Admin SDK >
   **Generate new private key** > Generate key. A JSON file downloads.
   - Keep this file private. Do not put it in any git repository or chat.
   - You paste its contents into Render in step 2, then delete the downloaded file.
5. **Firestore rules for the shop** (if not already published by the website work): the `products`
   collection must allow public reads and no client writes, for example:

   ```
   match /products/{productId} {
     allow read: if true;
     allow write: if false;   // only the backend (Admin SDK) writes
   }
   ```

   The Admin SDK ignores rules, so this does not block the backend.

## 2. Render console

### Option A: Blueprint (uses render.yaml)

1. https://dashboard.render.com > **New** > **Blueprint**.
2. Connect the GitHub repository `GLOWVAI-VENDOR-APPLICATION` and choose the branch that contains
   `render.yaml` (`glowvai-marketplace` until it is merged).
3. Render shows one service, **glowvai-vendor-api**. It asks for the value of
   `FIREBASE_SERVICE_ACCOUNT_JSON`: open the downloaded key file in a text editor, copy **all** of it
   (from `{` to `}`) and paste it. Raw JSON works; a base64-encoded copy of the file also works.
4. `VENDOR_TOKEN_SECRET` and `ADMIN_API_KEY` are generated by Render automatically.
5. Click **Apply**. The first deploy runs `npm install` in `backend/` and starts `node src/server.js`.

The Blueprint uses the **Starter** plan in the **Singapore** region (closest to India). You can pick
Free instead; a free service sleeps after 15 minutes idle and the first request then takes about a
minute, which also delays live order alerts to vendors.

### Option B: Manual web service

**New** > **Web Service** > connect the repository, then:

| Setting | Value |
|---|---|
| Root directory | `backend` |
| Runtime | Node |
| Build command | `npm install` |
| Start command | `node src/server.js` |
| Health check path | `/health` |

Environment variables (Environment tab):

| Key | Value |
|---|---|
| `NODE_ENV` | `production` |
| `FIREBASE_SERVICE_ACCOUNT_JSON` | full contents of the service account JSON file |
| `FIREBASE_PROJECT_ID` | `glowvai-v2` |
| `FIREBASE_STORAGE_BUCKET` | `glowvai-v2.firebasestorage.app` (the bucket from step 1.3) |
| `FIREBASE_DATABASE_URL` | `https://glowvai-v2-default-rtdb.firebaseio.com` |
| `VENDOR_TOKEN_SECRET` | 64 random hex characters: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` |
| `ADMIN_API_KEY` | another long random value (same command) |
| `ALLOWED_ORIGINS` | optional extra origins, comma-separated (glowvai.in, www.glowvai.in and localhost:3100 are always allowed) |

Do not set `PORT`; Render provides it. Every variable is described in `backend/.env.example`.

## 3. Check the deploy

Replace `<service>` with the Render URL, e.g. `https://glowvai-vendor-api.onrender.com`.

```bash
curl https://<service>/health
# → "env":"production", "firebase":"connected"

curl https://<service>/api/storefront/products
# → {"ok":true,"products":[...],"source":"firestore"}
```

If the deploy fails, open the service's **Logs**. "Refusing to start in production" names the
missing variable.

## 4. Admin key

The admin endpoints need the header `x-admin-key: <ADMIN_API_KEY>`. Copy the value from the
service's Environment tab. Keep it out of the website and the vendor app.

```bash
KEY='<ADMIN_API_KEY>'
API='https://<service>'
curl -H "x-admin-key: $KEY" "$API/api/admin/vendors?kycStatus=PENDING"
curl -X POST -H "x-admin-key: $KEY" "$API/api/admin/vendors/<vendorId>/approve"
curl -X POST -H "x-admin-key: $KEY" -H 'Content-Type: application/json' \
     -d '{"reason":"GSTIN does not match"}' "$API/api/admin/vendors/<vendorId>/reject"
curl -H "x-admin-key: $KEY" "$API/api/admin/products?approvalStatus=PENDING"
curl -X POST -H "x-admin-key: $KEY" "$API/api/admin/products/<productId>/approve"
curl -X POST -H "x-admin-key: $KEY" -H 'Content-Type: application/json' \
     -d '{"reason":"Photo is blurry"}' "$API/api/admin/products/<productId>/reject"
```

A product appears on the shop only when the product and its vendor are both APPROVED, it is an
active Skincare product with a shop category, and it has stock.

## 5. Point the website at the backend and rebuild /sellers

In the website repository:

1. Set `NEXT_PUBLIC_VENDOR_API_URL=https://<service>` in the website's hosting environment
   (and in its local `.env` if you build locally). The /sellers and /shop content security policies
   allow that origin only when the variable is set.
2. Rebuild the seller portal so the vendor app calls the new backend:

   ```bash
   VENDOR_APP_DIR="../GLOW VAI VENDOR/glowvai-vendor-app/mobile" \
   NEXT_PUBLIC_VENDOR_API_URL="https://<service>" \
   node scripts/build-sellers.mjs
   ```

   This exports the Expo web build into `public/sellers`.
3. Commit `public/sellers` and redeploy the website.

## Known limits

- **Vendor sign-in in production**: outside production the backend accepts the test OTP
  (`VENDOR_DEV_OTP`, default 4892). In production it only accepts a Firebase phone-auth ID token
  (`POST /api/auth/vendor/login` with `{ "firebaseIdToken": "..." }`). The vendor app does not yet
  run Firebase phone sign-in, so production vendors cannot sign in until that is added (enable
  Authentication > Sign-in method > Phone, and add `glowvai.in` to Authorized domains).
- Session tokens last 30 days and cannot be revoked individually; rotating `VENDOR_TOKEN_SECRET`
  signs every vendor out.
- Rate limiting and the socket rooms are in memory, so run a single instance.
